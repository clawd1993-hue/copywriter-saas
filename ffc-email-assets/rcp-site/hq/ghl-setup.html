1 · Architecture: one agency, one sub-account per client

  • Agency account = FFC's existing GHL agency (confirmed 2026-11-12). HNWA sub-accounts live under it. If it's the $97 Starter plan (3 sub-account cap), upgrade to $297 Unlimited before client #2.
  • Sub-account "HNWA Previews": one shared toll-free number, setter identifies as HNW Acquisition, serves all 50 preview funnels. Toll-free verification instead of 10DLC because 10DLC brand registration wants a US EIN and HNWA is a Spanish entity (for now).
  • Sub-account per client (created on close, day 0 of the 7-day clock): client's own local number, 10DLC registered under the client's EIN (they're a US business; they sign a one-page LOA, we file brand + campaign; 1–3 weeks typical, so file it the day they sign). Until 10DLC clears, the client sub-account can send via its own toll-free number as a bridge.
  • Setter workflow + Conversation AI prompt built once in Previews, then snapshot → cloned into every client sub-account. Per-client swaps: firm name, advisor first name, city, calendar link, asset floor.
  • Cost per client: ~$0 GHL (unlimited plan) + number ~$2/mo + 10DLC ~$4 brand + ~$15/mo campaign + SMS at ~$0.01–0.02 each. Negligible vs $5k/mo.
  • This replaces the Clawd ask. Nothing to relay.

  4. Inbound webhook (Automation → Trigger "Inbound Webhook"): maps the LP payload → create/update contact, set fields, add tag preview-<slug>, add tag by assets bucket (cold <250k · warm 250–500k · qualified 500k–1M · qualified-hi 1M+).
  5. Workflow "Preview setter" triggered by tag preview-*: - Wait 20s (feels human). - Send SMS = §3 message 1. - Hand the conversation to Conversation AI (bot prompt = §3) with "book Michael's 5-min call" as the goal and the calendar link as the only CTA. - Nudges: 24h and 72h if no reply, then stop. - Any inbound from a client-* tagged contact → the real client flow (later).
  6. Notification: every new preview contact → Michael's Telegram/email with slug + phone. Every conversation where the AI flags "sounds like a retiree, not an advisor" → human handoff to Michael.
  7. Test with Michael's own number on /for/dennis-okeefe/ before the first email goes out.

2b · Per-client sub-account playbook (day 0 after a close)

  1. Agency → Sub-accounts → create from snapshot "HNWA Client Setter". Name = firm. Timezone = theirs.
  2. Buy local number in their metro. Start toll-free verification as the bridge.
  3. Send client the 10DLC LOA + ask for: legal name, EIN, address, website, CCO contact. File brand + campaign same day.
  4. Swap custom values: firm, advisor_first, city, calendar_link, asset_floor, disclosure_line.
  5. Connect their calendar (Google/Outlook) to the booking calendar.
  6. Rebuild their funnel with HNWA_WEBHOOK=<their sub-account webhook> → deploy on their domain.
  7. Test end-to-end with Michael's number, then the advisor's.

3 · Preview-mode setter script ⚡ draft

Identity rule: until a firm signs, the setter is HNW Acquisition, never "[Firm]". We're showing the advisor what his retirees would get, so the voice is the concierge, but the sender is us.

Message 1 (auto, 20s after submit)

Hey [First], it's the concierge from HNW Acquisition 👋 You just registered on the class page we built for [Firm]. This is exactly what your retirees see.

Here's the class link 👉 [SAMPLE LINK]

Real quick, where are you based? Just want to make sure the class applies to you.

Then the real flow, same wording as the client version (FUNNEL-FLOW.md §4.2–4.6): bridge → assets → timeline → motivation → mirror → confirm. The advisor answers as himself or plays a retiree; either works.

Watch-gate, preview version (24h)

Hey [First], did you get a chance to look at the class? Doesn't matter if not. Here's what you've seen so far: registration → instant text → qualification on assets and timeline → the link. For a real retiree, the next message books them straight onto your calendar.

That's the whole machine. Want to see what it looks like running under your name, with your calendar on the end of it? Michael walks you through it in 5 minutes: [MICHAEL 5-MIN LINK]

If they reply anything like "who is this / what is this"

It's Michael's team at HNW Acquisition. You opened the preview page we built for [Firm] and registered on it, so you're getting the same texts a retiree would. No spam, this is the only sequence. Want 5 minutes with Michael to see the rest? [LINK]. Or reply STOP and I'll close it out.

If they ask about cost / how it works

Short version: you record a 45-min class once, we run it to [City] retirees with $500k+, this concierge qualifies every registrant and books the real ones onto your calendar. For the pilot there's no setup fee and no retainer. Michael covers the exact structure on the call: [LINK]

If they sound like an actual retiree (not the advisor)

Thanks for your interest. This page is a preview we built for [Firm] and the class isn't running yet. If you'd like to be told when it is, reply YES and we'll pass your details to [Firm]. (Flag to Michael. Do not continue the qual flow. Do not send a calendar link.)

Hard rules: no performance claims · no advice · STOP = stop · never claim to be [Firm] · one question per message.

3b · Setter expansion (Michael 2026-11-12, after SMS is live)

  • Voice platform decision (researched 2026-11-12): start with GHL native Voice AI ($97/mo flat or ~$0.045/min + model costs; inbound + outbound + booking inside the sub-account, no integration, snapshots cleanly). Upgrade path if the native voice/latency isn't good enough on a real client: Retell or Vapi (~$0.05–0.06/min infra + model, all-in ~$0.10–0.15/min) both publish native GHL connections and plug into the same number + workflow. Bland ~$0.14/min, no reason to pick it. Decision rule: native first, swap only after hearing it on client #1.
  • AI voice agent (GHL Voice AI): calls every new registrant within ~5 min of submit, same qual script as §3 (location → assets → timeline), books into the calendar, leaves a voicemail + falls back to SMS on no-answer. Needs the verified number. ~$0.10–0.15/min.
  • AI DM setter (Conversation AI on Instagram/Facebook/LinkedIn channels): for leads that arrive via social ads/DMs instead of the LP. Same prompt, channel-aware. Needs the client's FB page + IG connected to their sub-account.
  • Order: SMS first (this doc) → voice on client #1 once 10DLC clears → DMs when a client runs social ads.

4 · Wiring already in the template

  • LP posts JSON: {name, first_name, email, phone (E.164), assets, state_ok, slug, source, page} to WEBHOOK, then redirects to ty.html?fn=First&a=<bucket>&ph=<last4>. 4-second timeout so a slow webhook never blocks the redirect.
  • TY always shows "Check your phone"; reads ph to mask the last 4 digits. Small mobile-only sms: fallback link under it.
  • Consent line under the button: "By registering you agree to receive text messages and emails about this class from [Firm]. Msg & data rates may apply. Reply STOP to opt out." (For previews the sender is HNW Acquisition, not the firm; swap to "from HNW Acquisition on behalf of [Firm]" before go-live if counsel wants it.)
