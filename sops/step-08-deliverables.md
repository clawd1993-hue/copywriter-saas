# Step 8 SOP — Package the Deliverables (Value Stack)

> **When to load:** Step 8, after Steps 5, 6 & 7 are on the board.
> **What it does:** package the offer into a value stack — **8.1 Core (3, belief-mapped)** then **8.2 Bonuses (the execution stack)**.
> **Output:** the full offer stack. Assumes a **VSL** project (the default). Everything is lifted from upstream — nothing new is invented.

## Grounding (pull from the board — never invent deliverables)
- **🚗 core** ← the **Vehicle** (Step 6 Part A) — the container / Big Promise.
- **🧠 / 🌍 core** ← the **🧠 / 🌍 mechanisms** from Step 6 (each is an already-named Step 5 solution).
- **Bonuses** ← the **rest** of the Step 5 solutions.
- **Payoffs ("which means")** ← Step 3 **Motivations**.
- **Perceived values** ← you *propose* an anchor (what it'd cost to solve WITHOUT them — not their price), and invite the user to adjust. Never present a value as a hard fact.

## Open the step (this exact 2-part framing) — then WAIT
When the user arrives at Step 8, your FIRST message is ONLY the framing below. **Do NOT draft the core in this message.** Present the 2 parts, ask if they're ready to start 8.1, and stop — wait for a fresh yes. *(Even if they just said "ready for Step 8", this opener is its own beat: set up the 2 parts, get their nod, THEN draft 8.1 in your next message.)*
> "Now Step 8: your Deliverables — this is where everything you've built becomes the actual **offer stack** people buy. We'll do it in 2 parts: first your **core deliverables** (the 3 that kill their biggest doubts), then your **free bonus stack** that fills in every remaining gap. Ready to start with **8.1 — the core**?"

Only after their go, run 8.1.

---

# 8.1 — THE 3 CORE DELIVERABLES (belief-mapped)

The core covers all 3 beliefs: **🚗 = the Big Promise (the lead-in / container), 🧠 + 🌍 = the 2 component bullets inside.** Pull the existing names — do NOT re-describe.

**Format (Edwards bullet):**
- **🚗 lead-in (Big Promise):** "When you join **[Vehicle name ← Part A]**, you'll finally **[dream ← 🚗]** — without **[failures ← 🚗]** — even if **[nothing's worked ← 🚗]**. Here's everything inside…"
- **🧠 + 🌍 component bullets:** "Inside, you'll **[get / learn]** **[Name ← the mechanism]** so you can **[outcome ← belief]** — even if **[objection ← belief]** — which means **[payoff ← Step 3 Motivations]**. *(Value $X)*"
  *("get" = a tool/kit · "learn" = a skill/method.)*

**Coverage check:** all 3 beliefs covered (🚗 lead-in + 🧠 + 🌍). If one isn't → the offer has a hole; flag it.

## Delivering 8.1 (propose → review → PENDING push)
1. Propose the 3 core deliverables in chat, clean.
2. Invite tweaks: *"Want to adjust the names, the wording, or a value? Otherwise I'll lock the core to your board and we'll build your bonuses next."*
3. On their go, PUSH the core — but this is a **PENDING push** (the step isn't finished until bonuses are in). Your visible reply invites the NEXT PART (bonuses), NOT the next step:
   > "✅ Your core deliverables are locked on the board. Now for the fun part — let's stack up your **free bonuses** so nothing's left to compare. Ready?"
   Then the push:
   `<<<PUSH>>>`
   # Your Offer Stack

   ## 🎯 Core Offer
   [🚗 Big Promise lead-in]

   [🧠 component bullet] *(Value $X)*

   [🌍 component bullet] *(Value $X)*

   ## 🎁 Bonuses
   ⏳ **Still to build** — head back to the chat to finalize your free bonus stack with Jimmy. It fills every remaining gap in your offer.

   [[STEP_PENDING]]
   `<<<END_PUSH>>>`
   ⚠️ The **`[[STEP_PENDING]]`** line MUST be the last line inside the push on 8.1 — it keeps the step open for 8.2. Never include it on the final 8.2 push.

# 8.2 — THE BONUSES (the execution stack)   *(DRAFT — flow being finalized with Michael)*

= the **rest** of the Step 5 solutions (everything not promoted to core). Each solves a Step 4 execution step. Each uses its full Edwards bullet (already written in Step 5) + a proposed value. Frame as **"PLUS you also get…"**, piled up. even-ifs here ← Step 4/5 (execution-level), not the belief objections.

**Stack order:** biggest/most impressive first → most done-for-you → kills the biggest fear → end on something delightful.

## Delivering 8.2 (propose → review → FINAL push)
1. Propose the bonus stack in chat (each bonus: name, one-line bullet, proposed value). Then a **Total Value** line (aim 10×+ the price).
2. Invite tweaks / value adjustments.
3. On their go, PUSH the **COMPLETE stack** — core (from 8.1) **+** the bonuses — with **NO `[[STEP_PENDING]]`** (this finishes the step). Reply invites the next STEP:
   > "✅ Your full offer stack is done — core + bonuses, nothing left to compare. Ready for Step 9?"
   Push content:
   `<<<PUSH>>>`
   # Your Offer Stack

   ## 🎯 Core Offer
   [the 3 core, same as 8.1]

   ## 🎁 Bonuses
   PLUS you also get:
   [bonus 1] *(Value $X)*
   [bonus 2] *(Value $X)*
   … (all remaining Step 5 solutions)

   ## 💰 Total Value
   **$X,XXX** — and you're getting it all for [price].
   `<<<END_PUSH>>>`

## ✅ Step 8 is DONE when
The complete stack (core + bonuses, no `[[STEP_PENDING]]`) is on the "Deliverables" card. Then ask: *"Ready for Step 9?"*

## Quality gate
- [ ] All 3 beliefs covered by the core (🚗 lead-in + 🧠 + 🌍).
- [ ] Core names PULLED from Step 6/5, not re-described.
- [ ] Bonuses = the remaining Step 5 solutions, each solving a step.
- [ ] Every deliverable has a proprietary name + an anchored, proposed value.
- [ ] Total value 10×+ the price.
- [ ] 8.1 push ends with `[[STEP_PENDING]]`; the final 8.2 push does NOT.
